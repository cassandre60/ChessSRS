### Fixed in this audit

**F3 — iOS display name "Lichess" → "ChessSRS"** (`ed4f7a5b7`)
`ios/Runner.xcodeproj/project.pbxproj` set `INFOPLIST_KEY_CFBundleDisplayName`
to "Lichess" in all three Runner build configurations (Debug, Profile, Release),
overriding the correct "ChessSRS" in `Info.plist` at build time. iOS users would
see "Lichess" as the app name in the home screen and app switcher.

**F8 — Silent exception swallowing in PGN hash computation** (`1182d7188`)
`lib/src/import/pgn_importer.dart:45` had a bare `catch (_) {}` on the
tree-based PGN hash path. If tree parsing succeeded but `fenKey()` threw on a
malformed FEN header, the hash silently fell through to the text-based fallback.
The same PGN imported twice — once via tree, once via fallback — would produce
different hashes, defeating duplicate study detection. Now logs a warning with
the exception and stack trace.

### Open — require owner decisions

**F1 — Firebase project points at Lichess (`lichessv2`)**
All Firebase config files still use Lichess's own Firebase project:
- `lib/firebase_options.dart` — projectId `lichessv2`, storageBucket
  `lichessv2.appspot.com`, iosBundleId `org.lichess.mobileV2`
- `android/app/google-services.json` — same project, same API keys
- `android/app/src/debug/google-services.json` — same
- `ios/Runner/GoogleService-Info.plist` — same
- `ios/firebase_app_id_file.json` — same

**Impact:** FCM registrations, Crashlytics data, and analytics (even though
collection is disabled) go to Lichess's Firebase console. ChessSRS devices
appear in their dashboard. This is both a privacy concern (user device tokens
sent to a third party) and a functional dead end (Lichess won't send ChessSRS
push notifications).

**Decision required:** Either (a) create a ChessSRS Firebase project and
regenerate these files with `flutterfire configure`, or (b) strip Firebase
entirely and remove FCM/Crashlytics. Option (b) is simpler but loses the
notification infrastructure (C2 is currently KEEP). This cannot be fixed by code
edit alone — the files are generated by FlutterFire CLI and manual edits will be
overwritten.

**F4/F9 — iOS LichessWidgets extension is dead code**
`ios/LichessWidgets/` (1830 lines of Swift) contains Blog Feed Widget,
Broadcasts Widget, and Daily Puzzle Widget — all three are cut Lichess features
(C7, C6, C10). The extension target `LichessWidgetsExtension` is in the Xcode
build, the app group `group.org.chesssrs.app.LichessWidgets` is declared in
Runner entitlements, and the display name is still "LichessWidgets" (three build
configs). None of this code does anything useful.

**Recommendation:** Cut the entire iOS widgets extension. This is a ~33-reference
edit in `project.pbxproj` plus directory deletion, so it should be a dedicated cut
commit following CUT_PROPOSALS.md discipline.

**F5/F10 — Android broadcast widget is dead code**
`android/app/src/main/kotlin/org/chesssrs/app/widgets/BroadcastWidgetProvider.kt`,
`widget_broadcast.xml`, `widget_broadcast_info.xml`, `widget_broadcast_item.xml`,
and the strings in `values/strings.xml` ("Lichess Broadcasts") all implement the
broadcast homescreen widget from the cut Watch tab (C7). The widget is registered
in `AndroidManifest.xml` lines 183-193.

**Recommendation:** Cut the broadcast widget registration, Kotlin code, layouts,
and strings. Single commit.

**F2 — Android notification icon is Lichess-branded**
`drawable-*/ic_stat_lichess_notification.*` (5 files) are the Lichess horse head
icon, referenced from `AndroidManifest.xml` for push notification small icon.
Since notifications go to the wrong Firebase project (F1), this is cosmetic until
F1 is resolved.

### Deliberately not fixed

**F7 — Dead `hintUsed`/`multipleAttempts` params in ChessFsrsScheduler**
`chess_fsrs_scheduler.dart` adds `hintUsed` and `multipleAttempts` optional
named params to the `schedule()` override, but the `Scheduler` contract doesn't
expose them, so no call site can pass them. The FSRS rating adjustments for
hints/retries never fire. This is dead code rather than wrong behavior — the
scheduler always rates as first-attempt clean recall. Not an MVP blocker; the
params hint at future intent for hint-tracking features.

**M6, M10, M15 — Audit fixes without regression tests**
Per `docs/audit-disposition.md`: M6 (material accounting) is inherited upstream
unchanged. M10 (retry path) and M15 (hash offloading) are fixed but "ship
unproven" — the fixes exist and were verified by instrumentation, but no
automated test covers them because the test harness couldn't reproduce the
conditions. Documented and deliberate.

**org_lichess_mobile_keep.xml** — Resource shrinking keep rule. The filename has
"lichess" in it but the content is generic (`tools:keep="@drawable/*"`). Renaming
would require build system changes for zero user impact.

### What I'd watch after launch

1. **Firebase identity (F1)** — the most important unresolved issue. Every
   launch registers an FCM token with Lichess's project. Until resolved, the
   owner is sending device metadata to Lichess.

2. **Review test flakiness** — documented in Lessons Learned: `pumpAsync` waits
   a fixed 80ms of real time, causing flakes under CPU contention. Not a code
   bug, just a test infrastructure weakness that could mask real regressions.

3. **Database downgrade path** — `onDowngrade: onDatabaseDowngradeDelete`
   deletes the entire database on version downgrade. This is standard Flutter
   behavior but means a rollback from a newer schema version loses all
   repertoire data. Consider a backup-before-upgrade strategy for v1.0.

4. **iOS widgets extension build time** — 1830 lines of dead Swift code
   compiles on every iOS build. Not harmful but wastes build time.

5. **Large PGN imports** — the isolate-based hash works, but very large studies
   (thousands of variations) haven't been stress-tested for memory pressure.

### Go / No-go

**Conditional GO** for beta / personal use. The core loop (import → review → SRS
→ persist) is sound, tested, and the code quality is high for a fork of this
complexity. The domain layer is well-designed with proper separation, the schema
migrations are robust, and test coverage is good.

**Blocker for public release:** F1 (Firebase identity) must be resolved before
distributing to anyone beyond the owner. Sending device tokens to Lichess's
Firebase project is a privacy issue that would be disqualifying for any app store
review.

**Not blockers but should-fix before public release:**
- F4/F9/F5/F10: Dead widget code (iOS + Android) — technical debt, no user impact
- F2: Notification icon branding — cosmetic until F1 is resolved
